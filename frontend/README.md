# B2B AntiRisk — интерфейс с реальным API

Next.js 16, React 19, TypeScript. Интерфейс из `develop` подключён к FastAPI/Celery из `feature/backend`.
Данные проектов, документов, правил, решений и истории приходят с сервера. Локального демоанализа и
сохранения рабочих данных в localStorage нет; там хранится только выбранный режим анализа.

## Запуск всего приложения

Из корня репозитория:

```bash
cp .env.example .env
docker compose up --build
```

Интерфейс: http://localhost:3000. Nginx обслуживает статическую сборку и проксирует `/api` в backend.
Режим проверки выбирается во вкладке «Настройки», сохраняется в этом браузере и применяется ко всем
проектам при запуске и повторном анализе. Доступны LLM через ProxyAPI и поиск по ключевым словам.
Без серверного ключа ProxyAPI вариант LLM недоступен. Локальная NLI-модель отключена.
Режим документа сохраняется на сервере; повторяющиеся подписи режима в списках и результатах убраны.
Во всём интерфейсе используется Segoe UI с весом 700, включая подписи, таблицы и элементы форм.
Шрифт берётся из системы; при его отсутствии используются Arial и sans-serif.
Профиль API по умолчанию демонстрационный. Вход и полноценная авторизация пока не реализованы.

## Разработка фронтенда

Требуется Node.js 20.9+, запущенные backend/worker/PostgreSQL/Redis.

```bash
npm ci
cp .env.local.example .env.local
npm run dev
```

`/api` автоматически проксируется в `http://127.0.0.1:8000`. Для другого адреса backend измените
`API_PROXY_TARGET` (только сервер Next в режиме разработки). Для другого публичного API задайте
`NEXT_PUBLIC_API_BASE_URL` до сборки и настройте CORS на backend. Секреты в `NEXT_PUBLIC_*` не помещать.

```bash
npm run typecheck
npm test
npm run build
```

Сборка создаёт `out/`; статическому серверу нужен proxy `/api` (пример: `nginx.conf`).
Сборка не обращается к API и не требует ключей.

## Что подключено

- Создание проектов, список и поиск по проектам/файлам; собственные серверные счётчики каждого проекта.
- Multipart-загрузка реальных файлов до 100 МБ: PDF, TXT, ZIP, DOCX, DOC, RTF, ODT и изображения.
- Загрузка без автоматического старта: пользователь задаёт режим в «Настройках» и явно запускает анализ в проекте.
- Режимы из `GET /api/analysis-modes`; `analysis_mode` передаётся в start/rerun и сохраняется на сервере.
- Статусы очереди/обработки/ошибок, опрос каждые 2,5 секунды только во время обработки.
- Выбор отдельных документов ZIP с путями и ошибками; реальные страницы PDF и миниатюры.
- Оглавление, текст страницы, поиск по всему документу; подсветка подтверждённых цитат по PDF-координатам.
- Строковые UUID документов/замечаний, ссылка на документ с конкретной страницей и выбранным замечанием.
- Отдельная группа «Недостаточно данных» (`unknown`) для ошибок и неподтверждённых выводов;
  ненайденные условия пропускаются и не отображаются как успешная проверка.
- Статусы замечаний сохраняются PATCH-запросом; ошибки не маскируются успешными уведомлениями.
- CRUD правил, отключение и повторная проверка проекта с текущим набором правил.
- Переименование документа и скачивание серверных отчётов: краткий, подробный, протокол, PDF с пометками.
- Серверная история действий и профиль. Ошибки API, пустые состояния, загрузка и повтор запроса.

Базовая форма правила не перезаписывает скрытые расширенные настройки LLM. Для их изменения используйте
API. Изменения правил требуют повторной проверки проекта, чтобы получить новые результаты.
Настройки провайдера `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY` задаются для backend и worker в корневом
`.env`, не во фронтенде; примеры подключения и ограничения анализа — в [README проекта](../README.md#режим-анализа-и-подключение-proxyapi).
Доступный режим LLM означает наличие серверной конфигурации, а не проверенную доступность провайдера.
Ошибка запроса не переключает проверку автоматически на локальный режим.

## Основные файлы

| Файл | Назначение |
|---|---|
| `lib/api.ts`, `lib/api-types.ts` | HTTP, snake_case DTO → camelCase, ошибки, отмена запросов, multipart |
| `lib/types.ts` | Модели интерфейса с отдельными analysis/document ID |
| `components/use-workspace-data.ts` | Загрузка данных, опрос обработки, защита от устаревших ответов |
| `components/workspace.tsx` | Навигация и сохранение пользовательских действий |
| `components/document-workspace.tsx` | PDF/текст, координаты цитат, просмотр замечаний |
| `lib/navigation.ts` | Hash-маршруты с project/document/finding ID |
| `lib/report.ts` | Безопасное имя и скачивание серверного файла |
| `scripts/*.test.mjs` | Контракт клиента, маршруты, ошибки, загрузка, имена отчётов |

В браузерах с WebMCP доступны `read_document_findings`, `navigate_to_finding`,
`set_finding_review_status`; изменение статуса ожидает подтверждения API.
