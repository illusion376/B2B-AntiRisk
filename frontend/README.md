# B2B AntiRisk — фронтенд на Next.js

Интерфейс проверки документов по предоставленному макету. **Только фронтенд:** Next.js 16 (App Router), React 19, TypeScript, CSS и Lucide. API, база данных, авторизация и серверный анализ отсутствуют.

## Запуск

Требуется Node.js 20.9+ и npm.

```bash
npm ci
npm run dev
```

Открыть http://localhost:3000.

```bash
npm run typecheck
npm test
npm run build
```

Сборка создаёт статический сайт в `out/`. Для размещения подойдёт любой сервер статических файлов. Например, `npx serve@14 out`. Сборка не требует ключей или переменных окружения.

## Реализовано

- Рабочий экран по макету: боковая навигация, шапка документа, миниатюры страниц, текст документа и панель замечаний.
- Переходы по 54 демонстрационным страницам, ввод номера, масштаб 50–160%, режим перемещения документа мышью, разворачивание области чтения.
- Связь замечаний с текстом: выбор открывает страницу и подсвеченный фрагмент.
- Исходные данные: 3 критических замечания, 5 предупреждений, 12 успешных проверок. Степень риска замечания можно изменить в настройках правила.
- Фильтрация по категории, уровню и статусу; поиск по замечаниям; сворачивание групп; сортировка номера.
- Поиск по тексту всех страниц с подсветкой совпадений; фокус на поиске через Ctrl/Cmd+K.
- Подробности замечания в модальном окне, смена статуса и индикатор прогресса просмотра.
- Оглавление документа и список применённых правил.
- Раздел «Документы» со всеми проектами и кнопкой «Новый проект». Создание проекта с названием и описанием; одинаковые названия не допускаются. Каждый проект открывает собственный список файлов. Исходный демонстрационный документ можно открыть из его проекта.
- Выбор нескольких PDF/TXT/ZIP через кнопку или перетаскивание, проверка формата, пустых файлов, повторов и ограничения 50 МБ на файл.
- Имитация обработки: «В очереди» → «Обрабатывается» с прогрессом → «Обработано · демо» за 6 секунд. Статус вычисляется по времени добавления и сохраняется при переходах и перезагрузке; никакого анализа или распаковки ZIP нет.
- Раздел «Правила»: добавление, редактирование названия, описания, категории и степени риска (высокий, средний, низкий), переключение активности, поиск и фильтр.
- Удаление правила только после диалога «Точно удалить?»; отмена, Escape и закрытие окна ничего не удаляют.
- Отключённые и удалённые правила исключаются из демонстрационных замечаний и отчёта. Новые правила не создают вымышленных результатов проверки. Низкий риск не превращает замечание в успешную проверку.
- Низкий риск отображается зелёным в карточках, форме редактирования, таблице и аннотациях документа.
- Сохранение проектов, сведений о файлах, правил и статусов в браузере с валидацией восстановленных данных и предупреждением при недоступном хранилище. Данные предыдущей версии автоматически мигрируют без потери правил, статусов и названия демонстрационного документа.
- История действий в текущей сессии, переименование файла, уведомления.
- Скачивание CSV-отчёта в UTF-8 с BOM (совместим с Excel); отчёт содержит результаты включённых правил и текущие статусы.
- Адаптивная вёрстка: на узких экранах документ и замечания переключаются вкладками.
- Семантические элементы, подписи контролов, клавиатурный фокус, закрытие диалогов через Escape, учёт reduced motion.

## Улучшения интерфейса

- Разделы проектов, файлов, правил, истории и результатов оформлены в едином стиле: коралловый фон, светлая рабочая область, боковое меню, чёрные кнопки и компактные таблицы.
- Страница результатов анализа обновлена для настольных экранов: панель страниц, просмотр документа, поиск, вкладки замечаний, фильтры и прогресс проверки. Новые стили ограничены контейнерами `.dashboard-canvas` и `.dashboard-shell`; базовый `app/globals.css` не изменён. Мобильная версия в этой итерации не дорабатывалась.
- Рабочее пространство сразу показывает список проектов: шесть карточек сводки удалены. Доступны поиск по описанию и файлам и сортировка проектов.
- Фильтры проектов по статусу и постраничный вывод по 8 проектов. Счётчики в фильтрах и таблице рассчитываются из текущих данных браузера.
- Поиск документов проекта и фильтры статуса с актуальными счётчиками.
- Навигация через hash-маршруты: Back/Forward и перезагрузка сохраняют проект, страницу и выбранное замечание. Работает на статическом хостинге.
- Видимые счётчики и сброс фильтров замечаний; закрытие поиска убирает поисковый фильтр.
- Клавиатурное переключение вкладок стрелками/Home/End, контекст выбранного замечания, процент просмотра и улучшенный контраст.
- Отсутствие результатов проверки отличается от успешной проверки без замечаний.
- CSV защищён от интерпретации пользовательских полей как формул таблицы.
- `npm test`: 5 проверок разбора и сериализации маршрутов, валидации параметров и изоляции стилей нового интерфейса. Новые зависимости не добавлены.

## Ограничения демонстрации

`Проект контракта.pdf` — название демонстрационного документа. В интерфейсе отображается HTML-текст, а не настоящий PDF. Данные страниц и результаты проверки заданы локально; автоматический анализ не запускается. Выбор пользовательских PDF/TXT/ZIP реализован только как фронтенд-заглушка: сохраняются название, тип, размер и время добавления. Содержимое файлов не читается, не хранится и не передаётся на сервер. Просмотр и скачивание выбранных файлов не реализованы. Проекты, сведения о файлах, правила и статусы сохраняются в localStorage текущего браузера. История действий существует до перезагрузки. Данные не синхронизируются между браузерами и устройствами. Скачивается CSV, не PDF-отчёт.

Текст и рекомендации служат для показа интерфейса и не являются юридическим заключением. Пример воспроизводит содержание предоставленного макета с согласованными связями замечаний и страниц.

## Подключение будущего бэкенда

1. Заменить данные из `lib/mock-data.ts` ответами API, сохранив тип `Finding` из `lib/types.ts`.
2. В `workspace.tsx` подключить получение проектов, документов, замечаний и правил; заменить `uploadFiles()` реальной загрузкой и состояния из `getProcessing()` статусами API.
3. В обработчиках `changeStatus`, изменения правил и переименования вызвать соответствующие API-методы.
4. Для настоящих PDF заменить `getPageSections()`/`document-paper` на PDF-рендерер и связать аннотации с координатами из API.
5. При необходимости заменить генерацию CSV в `lib/report.ts` скачиванием отчёта с сервера.

UI и демонстрационные данные разделены. Серверных маршрутов, Server Actions, запросов к внешним сервисам и секретов в проекте нет. Для серверного сохранения замените localStorage в workspace.tsx на API; данные имеют версию схемы и стабильные идентификаторы правил.

## WebMCP

В поддерживающих браузерах приложение регистрирует `read_document_findings`, `navigate_to_finding`, `set_finding_review_status`. Они работают с тем же состоянием, что и интерфейс. В браузерах без WebMCP интеграция пропускается.

## Размещение

Next.js использует `output: 'export'`: https://nextjs.org/docs/app/guides/static-exports.
Локальные файлы шрифтов и сторонние CDN не требуются. Шрифты системные.
